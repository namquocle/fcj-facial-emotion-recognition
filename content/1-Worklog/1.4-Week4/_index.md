# WEEK 4 (13/07 - 19/07): PROJECT IMPLEMENTATION – PHASE 1: SETTING UP AMAZON S3, DYNAMODB, AND IAM SECURITY CONFIGURATION

## 1. Weekly Objectives

* Implement Phase 1 of the project in a real AWS environment.
* Create an Amazon S3 bucket for storing uploaded images and a DynamoDB table for storing emotion analysis logs.
* Configure IAM Roles for AWS Lambda and IAM Users for the frontend application following the **Principle of Least Privilege**.

## 2. Tasks Completed

### Storage Resource Setup (Amazon S3)

* Created an Amazon S3 bucket named `my-facial-emotion-recognition-2026` in the `ap-southeast-1` (Singapore) region to provide low-latency access for users in Vietnam.
* Enabled **Block Public Access** to protect uploaded user images from unauthorized access.
* Configured default server-side encryption using **SSE-S3** to secure data at rest.

### Database Resource Setup (Amazon DynamoDB)

* Created a DynamoDB table named `FaceEmotionLogs`.
* Configured the primary key:

  * **Partition Key:** `LogID`
  * **Data Type:** String
* Designed the table to store randomly generated UUID values for each analysis record.
* Selected the **On-Demand Capacity Mode** to minimize costs during the development and testing phase.

### IAM Security Configuration

#### IAM User for the Frontend Application

* Created an IAM user named `streamlit-s3-uploader`.
* Developed a custom IAM policy allowing only the `s3:PutObject` action on the following resource:

```text
arn:aws:s3:::my-facial-emotion-recognition-2026/*
```

* Generated an **Access Key ID** and **Secret Access Key** for integration into the Streamlit web application configuration.

#### IAM Role for AWS Lambda

* Created an execution role named `LambdaEmotionRecognitionRole`.

* Attached the AWS-managed policy `AWSLambdaBasicExecutionRole` to allow Lambda functions to:

  * Create CloudWatch Log Groups.
  * Create CloudWatch Log Streams.
  * Write logs to Amazon CloudWatch.

* Created an inline policy granting the Lambda function permission to:

  * Read objects from Amazon S3 using `s3:GetObject`.
  * Invoke Amazon Rekognition using `rekognition:DetectFaces`.
  * Write records to DynamoDB using `dynamodb:PutItem`.

## 3. Knowledge and Skills Acquired

### Information Security and IAM Policy Design

* Gained a deeper understanding of IAM policy development using JSON.
* Learned the key components of IAM policies:

  * **Effect** – Defines whether an action is allowed or denied.
  * **Action** – Specifies the AWS operations that can be performed.
  * **Resource** – Identifies the specific AWS resources affected by the policy.

### Cloud Resource Management

* Developed practical experience in provisioning and configuring foundational AWS resources required for a serverless application architecture.

## 4. Challenges and Troubleshooting

### Challenge

While creating the IAM policy for DynamoDB access, the initial configuration used:

```json
"Resource": "*"
```

This resulted in a security warning generated by AWS security monitoring tools, including AWS Security Hub, because the policy granted overly broad permissions.

### Resolution

* Applied the **Principle of Least Privilege** by restricting access to the specific DynamoDB table ARN.
* Retrieved the exact ARN of the `FaceEmotionLogs` table:

```text
arn:aws:dynamodb:ap-southeast-1:account-id:table/FaceEmotionLogs
```

* Replaced the wildcard resource with the table-specific ARN in the IAM policy to eliminate unnecessary permissions and improve security compliance.

## 5. Outcomes

* Successfully provisioned the Amazon S3 bucket and DynamoDB table required for the project.
* Completed the IAM security configuration following AWS security best practices.
* Ensured proper separation of permissions between services, preventing privilege escalation and cross-service access vulnerabilities.

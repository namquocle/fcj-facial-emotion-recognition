# WEEK 6 (27/07 - 02/08): PROJECT IMPLEMENTATION – PHASE 3: CONFIGURING S3 EVENT TRIGGERS AND TESTING AUTOMATED INTEGRATION

## 1. Weekly Objectives

* Configure automatic Lambda invocation when new objects are uploaded to Amazon S3.
* Ensure the end-to-end workflow from Amazon S3 → AWS Lambda → Amazon DynamoDB operates seamlessly.
* Monitor and troubleshoot the system using Amazon CloudWatch Logs.

## 2. Tasks Completed

### S3 Event Trigger Configuration

* Accessed the configuration page of the AWS Lambda function `FaceEmotionRecognizer`.
* Added a new trigger of type **Amazon S3**.
* Selected the corresponding S3 bucket and configured the event type as:

```text
All object create events
```

which includes object creation through PUT, POST, and COPY operations.

* Configured an event filter with the following prefix:

```text
uploads/
```

to ensure that the Lambda function is triggered only when image files are uploaded to the designated folder. This prevents unnecessary executions caused by objects created elsewhere in the bucket.

### Environment Variable Configuration

* Created an environment variable named:

```text
DYNAMODB_TABLE_NAME
```

and assigned the value:

```text
FaceEmotionLogs
```

* Updated the source code to retrieve the table name dynamically using:

```python
os.environ.get('DYNAMODB_TABLE_NAME')
```

This approach improves maintainability and simplifies future configuration changes.

### Integration Testing

* Uploaded multiple sample images containing different facial expressions (happy, sad, and angry) into the `uploads/` folder of the S3 bucket using the AWS S3 Console.
* Accessed **Amazon CloudWatch Logs** and reviewed the log streams generated by the Lambda function.
* Verified the processing workflow by checking:

  * Uploaded image names
  * Number of detected faces
  * Emotion analysis results returned by Amazon Rekognition
* Opened the **Amazon DynamoDB Console** and navigated to **Explore Table Items** to confirm that analysis records were successfully stored in the `FaceEmotionLogs` table with accurate real-time data.

## 4. Challenges and Troubleshooting

### Challenge

The Lambda function was being triggered multiple times for the same uploaded image, resulting in:

* Unnecessary Lambda executions.
* Increased resource consumption.
* Duplicate records being inserted into DynamoDB.

### Resolution

* Investigated the S3 event notification configuration and discovered that no object prefix filter had been configured initially.
* As a result, every object creation event within the bucket triggered the Lambda function.
* Updated the configuration by restricting the trigger scope to the following prefix:

```text
uploads/
```

This ensured that only intended image uploads generated events and eliminated redundant Lambda executions.
